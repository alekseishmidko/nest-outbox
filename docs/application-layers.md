# Слои приложения

## Цель

Этот документ фиксирует слои backend-приложения и правила размещения кода. Основная задача архитектуры: сохранить SQL видимым и управляемым, но не смешивать его с HTTP и бизнес-логикой.

## Controllers

`controllers` отвечают только за HTTP API:

- принимают запрос;
- применяют DTO;
- вызывают service;
- возвращают ответ.

Контроллеры не содержат SQL, транзакций и бизнес-алгоритмов.

## Services

`services` содержат бизнес-логику:

- проверяют бизнес-правила;
- координируют несколько repositories;
- запускают транзакционные сценарии;
- создают Outbox-события через соответствующий слой.

Service не должен знать детали HTTP.

## Repositories

`repositories` отвечают за доступ к данным:

- содержат raw SQL;
- используют `mysql2` prepared statements;
- возвращают доменные данные в понятной форме;
- не принимают непроверенный пользовательский ввод.

Repository не должен принимать `Request`, DTO контроллера или HTTP-объекты.

## Types

`types` содержит типы конкретного модуля:

- доменные record-типы, которые возвращает repository;
- SQL-row типы для `mysql2`;
- локальные helper-типы модуля.

Типы не должны объявляться внутри repository, если они используются снаружи или описывают отдельную сущность. Для каждого значимого типа создается отдельный файл.

## Modules

`modules` изолируют логические области приложения:

- `users`;
- `maps`;
- `orders`;
- `media`;
- `outbox`;
- `database`;
- `metrics`;
- `health`;
- `seed`.

Каждый модуль должен иметь понятную зону ответственности и собственную документацию.

## Workers

`workers` выполняют фоновые задачи:

- polling таблицы `outbox_events`;
- retry событий;
- периодические технические задачи.

Worker не должен напрямую реализовывать бизнес-логику конкретного домена. Он должен вызывать обработчик или service.

## Common

`common` содержит только общую инфраструктуру:

- filters;
- guards;
- interceptors;
- pipes;
- utils.

В `common` нельзя складывать бизнес-логику, SQL-запросы и случайные helper-функции без четкого владельца.

## Направление зависимостей

Рекомендуемый поток:

`controller -> service -> repository -> database`

Для Outbox:

`service -> outbox repository -> outbox worker -> handler -> target service`

## Правила чистоты

- SQL находится только в repositories, database и migrations.
- DTO используются на HTTP-границе.
- Env-конфигурация валидируется до старта приложения.
- Публичные классы и методы документируются JSDoc на русском языке.
- Каждый модуль должен иметь README с целью, задачами и примерами.
